# Experiments

Everything here is launched with a single `sbatch` from the worktree root
(`/juice2/scr2/kelvinkn/other_work/edwards/improve_wt`).  All jobs use
`--account=nlp --partition=jag-standard --gres=gpu:titanrtx:1 --mem=60g
--cpus-per-task=10`, call `/juice2/scr2/kelvinkn/conda_envs/physionet/bin/python` by
absolute path, and write logs to `experiments/logs/` on `/juice2` (never `/tmp`, which is
node-local and invisible to other nodes).  Every script recreates its own output
directories, prints the node / GPU / torch version at the top, and exits non-zero on
failure.

`titanrtx` is Turing **SM 7.5**, the same architecture as the grader's T4; the CUDA
allocator is capped to **14.5 GiB** in every GPU job so an OOM here means an OOM there.
bf16 is never used — SM 7.5 has fp16 tensor cores but no native bfloat16.

## Contents

| File | What it does |
|---|---|
| `configs/*.yaml` | One config per rung of the ablation ladder (PLAN.md §2), generated by `make_configs.py` |
| `make_configs.py` | Regenerates `configs/` from `chagas.config.ExperimentCfg` so the YAMLs can never drift from the dataclasses |
| `run_capped.py` | Runs an **unmodified** organiser wrapper (`train_model.py` / `run_model.py`) under the 14.5 GiB cap and reports peak memory and wall time |
| `run_ladder.sh` | One ladder rung end to end: train → infer on Test A and Test C → `evaluate_model.py` → `eval_report.py` |
| `build_test_C.py` | Builds Test C: the held-out set perturbed the way the organisers perturbed the hidden cohorts |
| `eval_report.py` | A/B/C table, per-source mean probability, score by age decile, C−A gap |
| `memory_smoke.py` | PLAN §5 item 11: one stage-2 optimiser step at batch 16 × 5000, fp16, under the cap |
| `batch_*.sh` | The sbatch entry points (below) |
| `results/<row>/` | `report.md`, `summary.csv`, `per_source.csv`, `per_age_decile.csv`, `predictions_{A,C}.csv`, `scores_A.csv`, and the trained `model/` |

## How to run

```bash
cd /juice2/scr2/kelvinkn/other_work/edwards/improve_wt

# 0. tests (CPU; also runnable on the login node)
/juice2/scr2/kelvinkn/conda_envs/physionet/bin/python -m pytest tests -q
sbatch experiments/batch_slurm_tests.sh        # same suite on a GPU node

# 1. does stage 2 fit in a T4?  ALWAYS run this before any row >= 5.
sbatch experiments/batch_memory_smoke.sh

# 2. end-to-end contract check on the 400-record smoke set
sbatch experiments/batch_e2e_smoke.sh

# 3. build Test C once (CPU job, ~73,300 records)
sbatch experiments/batch_build_test_C.sh

# 4. the ablation ladder, one rung at a time
sbatch experiments/batch_ladder_row0.sh        # a72c51c-equivalent baseline
sbatch experiments/batch_ladder_row1.sh        # + defect fixes
sbatch experiments/batch_ladder_row2.sh        # + soft labels, w_pos=5, 5x oversampling
sbatch experiments/batch_ladder_row2b.sh       #   variant: no oversampling
sbatch experiments/batch_ladder_row3.sh        # + augmentation suite
sbatch experiments/batch_ladder_row4.sh        # + FiLM demographics
sbatch experiments/batch_ladder_row5.sh        # + two-stage fine-tuning with LLRD
sbatch experiments/batch_ladder_row6.sh        # + auxiliary heads          (optional)
sbatch experiments/batch_ladder_row7.sh        # + margin-ranking loss      (optional)
sbatch experiments/batch_ladder_row8.sh        # + domain-adversarial head  (optional)
sbatch experiments/batch_ladder_row9.sh        # + 2-seed ensemble

# 5. the final configuration on the full 292,885-record split, 2 seeds
sbatch experiments/batch_full_final.sh
```

Rows are cumulative (each adds to the previous, like Hong et al. 2025 Table 2), so run
them in order and read `experiments/results/<row>/report.md` before queueing the next.
Rows 0–4 keep the encoder frozen and take roughly as long as the baseline run; rows 5+
unfreeze the backbone and are given a 2-day wall clock with a 40 h internal budget.

`run_ladder.sh` passes the config through `$CHAGAS_CONFIG`.  `train_model.py` takes no
config argument and is never edited; `team_code.train_model` reads the environment
variable and falls back to `chagas.config.default_config()` (= row 5) when it is unset,
which is what the judged container will do.

## Acceptance rule

From PLAN.md §2, applied to every rung:

> **A must not decrease by more than 0.005, and the C−A gap must not widen.**
> Otherwise the change is reverted.

Read it off `results/<row>/report.md`:

* the `A`, `B` and `C` rows of the **Views** table give the challenge score, AUROC,
  AUPRC, the prevalence ceiling (the score is recall in the top 5%, so it is capped at
  `0.05 / prevalence` — the raw number is not interpretable without it) and the number
  of records that failed;
* the **C − A gap** line is the headline for robustness;
* **per-source mean probability** is the source-shortcut diagnostic: SaMi-Trop is 100%
  positive and PTB-XL 100% negative, so a model can score on Test A by recognising the
  cohort.  Test B removes that, which is why B is the honest in-distribution number;
* **score by age decile** is the age-shortcut diagnostic.  ELSA-Brasil is a broader,
  asymptomatic population; if FiLM's gain is entirely explained by age, prefer
  `demographics: "none"`.

Rows 6–8 are judged on **C and B**, not A — they are robustness changes and are expected
to cost a little in distribution.

## Baseline to beat

`a72c51c`, 100k subsample, 16 epochs, frozen encoder, patient-grouped held-out split
(run **16878337**):

| View | Challenge score | AUROC |
|---|---|---|
| **A** full held-out (73,300 records, 1,662 positives, 2.27% prevalence) | **0.434** | **0.858** |
| **B** CODE-15 only (68,575 records, 1,336 positives) | **0.440** | 0.858 |
| **C** perturbed | not measured — this is what row 0 produces |

Note that row 0 is a *reconstruction* of that baseline inside the new harness, not the
old code: it restores `nk.ecg_clean`, the missing padding mask, hard labels, plain BCE
with inverse-frequency sampling, concatenated demographics, a frozen encoder and no
augmentation, but two things cannot be turned off — the FFT `scipy.signal.resample`
(replaced unconditionally by `resample_poly`) and "train on every record and ship epoch
16" (this harness always holds out a patient-grouped 10% and selects on it).  The numbers
above stay the authoritative `a72c51c` result.

## Notes

* `build_test_C.py` seeds each record's perturbation from the record's own stem, so the
  output is reproducible and independent of the worker count — two ladder rows are
  always scored on byte-identical Test C data.
* `eval_report.py` scores a record that produced no output, or a NaN probability, at the
  worst possible rank rather than dropping it.  Dropping would silently flatter the model
  by removing the records it could not handle.
* `run_ladder.sh` fails the job if any `.ckpt` appears outside `model_folder`.  The
  judged container runs with `WORKDIR /challenge`, and an implicit Lightning
  `ModelCheckpoint` there would write a full checkpoint per epoch into the repo root.

## Ladder results, rows 2 and 3 (2026-09-25, same subsample/seed; SLURM 17591923, 17591924; 5h08 each, frozen encoder)

| Row | A chall / AUROC | B chall / AUROC | C chall / AUROC | C−A | PTB-XL / CODE-15 / SaMi-Trop mean prob | best val epoch |
|---|---|---|---|---|---|---|
| 0 baseline | 0.412 / 0.848 | 0.423 / 0.851 | 0.408 / 0.846 | −0.004 | 0.077 / 0.356 / 0.640 | (all 16 epochs, no early stop) |
| 2 +soft labels, w_pos 5, 5× oversample (+row-1 fixes) | **0.427** / 0.856 | 0.428 / 0.851 | **0.351** / 0.821 | **−0.076** | 0.078 / 0.639 / 0.807 | 8 of 12 |
| 3 +augmentation | 0.407 / 0.837 | 0.415 / 0.836 | 0.374 / 0.825 | −0.033 | **0.316** / 0.623 / 0.779 | 5 of 9 |
| 5 full (+FiLM, +two-stage FT) | 0.435 / 0.854 | 0.436 / 0.850 | 0.425 / 0.847 | −0.010 | 0.008 / 0.627 / 0.798 | stage-2 epoch 0 |

Findings:
1. **Row 1 was skipped**, and row 0→1 changes three things (padding mask, neurokit→butterworth cleaner,
   early stopping), so the C collapse between row 0 (−0.004) and row 2 (−0.076) cannot yet be attributed
   between those fixes and the label/weighting change. Row 1 must run before either is accepted.
2. **Augmentation does what it is for**: C−A narrows from −0.076 to −0.033 and PTB-XL's mean probability
   rises from 0.078 to 0.316, i.e. the augmentation (resample round-trip, device filters) removes a
   PTB-XL fingerprint — consistent with PTB-XL being the only 500 Hz source (the others are 400 Hz),
   the "original sampling frequency" confounder Van Santvliet et al. warned about. Cost: A −0.020.
3. **Row 5 has the best C but the strongest source separation** (PTB-XL 0.008). Since row 3 had removed
   it, FiLM (PTB-XL is European, different age/sex mix) and/or the unfrozen encoder re-learn a source cue
   that survives our Test-C perturbations. Row 4 and a `demographics: none` ablation separate these.
4. Validation scores (~0.37) sit below test A because the 10% val split has 6.4% prevalence (ceiling 0.78).
5. Acceptance rule: row 2 vs 0 fails on the C−A gap; row 3 vs 2 fails on A (−0.020) but halves the gap.
   The rule assumed monotone gains; rows 2/3 show a real in-distribution vs robustness trade-off.
